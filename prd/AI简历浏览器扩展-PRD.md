## 1. 产品定义

### 1.1 产品名称

**AI 简历岗位助手**

侧边栏副标题：**投递副驾 Agent**

### 1.2 一句话定位

> 用户浏览招聘岗位时，插件在当前页面精准识别岗位，并调用其 AI 简历账号中的真实简历完成匹配判断、收藏、沟通准备和受控回填。

### 1.3 产品目标

1. 把 AI 简历能力带到用户正在浏览岗位的现场，减少复制 JD、切换页面和重复上传简历。
2. 识别岗位时优先保证字段对应正确，不以“尽量有结果”为理由拼接错误公司、薪资或岗位详情。
3. 让用户在一次侧边栏流程中完成“识别岗位、选择简历、判断匹配、收藏并准备”。
4. 保留用户对最终投递和消息发送的决定权。
5. 复用现有账号、简历、AI、Token 钱包和网页端收藏，不形成数据孤岛。

### 1.4 核心价值

- **入口近**：招聘页面提供悬浮入口、插件图标和右键菜单。
- **数据真**：分析基于用户已保存简历，不凭空编造经历。
- **岗位准**：采用结构化数据、平台适配器和标题一致性校验。
- **结果可回流**：岗位收藏与完整详情进入网页端“我的收藏”。
- **操作少**：打开侧边栏即可自动识别当前岗位，必要时再手动刷新。

## 2. 用户与场景

### 2.1 目标用户

- 已有一份或多份简历、正在主动找工作的用户。
- 经常同时浏览多个国内招聘平台的校招、社招和转岗用户。
- 不确定自己的真实经历是否足以支持当前岗位，需要快速判断优先级的用户。
- 希望减少重复填写申请表，但仍愿意在提交前自己检查的用户。

### 2.2 核心场景

```text
用户打开具体岗位详情
  -> 点击页面右侧 AI 悬浮入口
  -> Chrome 打开插件侧边栏
  -> 插件识别当前岗位并显示公司、薪资、地点、技能和 JD
  -> 用户选择已有简历
  -> 点击“开始投前准备”
  -> Agent 给出匹配判断、证据、缺口、建议和沟通开场白
  -> 岗位保存到“我的收藏”
  -> 用户选择修改简历、复制开场白或进入受控回填
```

## 3. 产品原则

### 3.1 准确优先

- 平台适配器只读取当前选中岗位的明确容器。
- 岗位标题不一致时，不合并结构化数据与页面数据。
- 无法确认岗位详情时提示失败，不读取整页文字后猜测。
- 岗位 JD 只保留岗位职责、任职要求、技能和明确福利，不混入招聘官、公司介绍、微信分享、地图或按钮文案。

### 3.2 用户控制

- 插件不会自动点击最终提交。
- 插件不会自动发送招聘聊天消息。
- 回填后必须由用户核对页面字段。
- 只有用户点击入口、右键菜单或侧边栏按钮时才处理页面。

### 3.3 低理解成本

- 不要求用户理解知识库、提示词、模型或 Agent 编排。
- 首页流程保持“当前岗位、选择简历、开始准备”三个核心区块。
- 普通页面不展示内部 Token 估算、解析器或接口概念。

## 5. 功能需求

### FR-01 招聘页面悬浮入口

1. 只在 Manifest 已授权的招聘网站注入。
2. 默认显示为 48 × 48 px 的 `AI` 品牌按钮，靠页面右侧固定，不改变宿主页面布局。
3. 鼠标悬停或键盘聚焦时展开“打开岗位助手”。
4. 使用 Shadow DOM 隔离招聘网站 CSS。
5. 点击后立即调用 `chrome.sidePanel.open()`，同时异步识别当前岗位。
6. 识别成功显示短提示；识别失败仍打开侧边栏，并在侧边栏显示可理解的原因。
7. 重复热注入时必须先销毁旧入口，页面只能存在一个实例。
8. 小屏页面调整到右下方，避免覆盖页面主操作区。
9. 遵守 `prefers-reduced-motion`，键盘可聚焦并具备清晰焦点态。

### FR-02 账号连接

1. 本地开发网页地址为 `http://localhost:5173`，API 为 `http://localhost:8000`。
2. 生产网页与 API 为 `https://aijianli.tech`。
3. 插件通过 `chrome.identity.launchWebAuthFlow` 打开 `/extension/connect`。
4. 已登录用户确认后签发一次性授权码；未登录用户先完成登录。
5. 插件使用授权码调用 `/api/extension/auth/exchange`，只在 `storage.local` 保存受限访问令牌。
6. 插件不得读取网页 refresh token、密码、Cookie 或验证码。

### FR-03 当前岗位识别

输出字段：

| 字段 | 含义 | 要求 |
|---|---|---|
| `sourceTitle` | 岗位名称 | 必填，不得是“职位描述”“微信分享”等 UI 标题 |
| `company` | 公司名称 | 只取当前岗位对应公司 |
| `location` | 城市/区域 | 如“深圳-南山区” |
| `address` | 完整工作地址 | 有公开信息时保存，不用公司注册地址代替 |
| `salary` | 薪资 | 保留 K、千、万、月薪、年薪和薪数 |
| `skills` | 技能标签 | 去重后的明确技术、工具或岗位技能 |
| `jdText` | 岗位详情 | 完整职责与要求，可滚动展示，不进行 UI 截断 |
| `sourceUrl` | 原岗位地址 | 去除无意义追踪参数，必须可返回 |
| `sourcePlatform` | 识别平台 | 标准化平台名 |
| `sourceOriginal` | 原始来源 | 转载岗位可保留原来源说明 |

识别优先级：

1. 当前平台精确 DOM 适配器。
2. 页面内 `JobPosting` JSON-LD。
3. 标题一致时合并两者，以更完整且更具体的字段为准。
4. 严格语义回退。
5. 无可靠结果时返回错误。

### FR-04 平台适配

| 平台 | 域名 | 当前策略 |
|---|---|---|
| BOSS 直聘 | `*.zhipin.com` | 校验左侧激活卡片与右侧详情标题，等待 SPA 切换稳定 |
| 前程无忧 | `*.51job.com` | 读取职位头、职位详情、公司卡片、工作地址和 JSON-LD |
| 智联招聘 | `*.zhaopin.com` | 读取详情根节点、职位摘要、公司与地址 |
| 猎聘 | `*.liepin.com` | 读取职位申请区、岗位属性和详情容器 |
| 拉勾 | `*.lagou.com` | 读取职位头、标签、详情与地址模块 |
| 58 同城 | `*.58.com` | 分类招聘详情适配器 |
| 赶集 | `*.ganji.com` | 分类招聘详情适配器 |

新增平台必须同步 Manifest 域名、适配器、背景域名判断、测试样例、Skill 契约和本 PRD。

### FR-05 投前准备 Agent

1. 用户必须已连接账号并至少有一份简历。
2. 默认选择最近更新简历，允许用户切换。
3. Agent 输出匹配分数、可用证据、能力缺口、下一步建议和沟通开场白。
4. 分数只用于岗位优先级判断，不宣传为 Offer 概率。
5. 不得把 JD 中未在简历出现的技能伪造成用户经历。
6. AI 调用沿用现有 Token 钱包与计费规则；纯页面识别与打开侧边栏不调用模型。

### FR-06 收藏岗位

1. 保存岗位全部识别字段、选定简历、匹配结果和状态。
2. 同一用户、同一规范化岗位 URL 再次收藏时更新原记录。
3. 收藏列表过滤无效 UI 标题。
4. 旧收藏缺少公司、平台、地点或地址时标记“待重新识别”，不伪造缺失信息。
5. 网页端详情弹窗展示平台、来源、公司、薪资、地点、完整地址、技能和完整 JD。
6. “查看原招聘页”必须打开该收藏的 `source_url`。

### FR-07 回填与投递边界

1. 只回填能够识别的普通输入框、文本域或平台已适配字段。
2. 不覆盖非空字段，除非用户明确确认。
3. 不处理招聘网站密码、验证码或支付信息。
4. “一键投送”只允许打开可见投递入口或完成表单回填。
5. 最终提交、发送消息、选择附件和确认信息由用户完成。

## 6. 信息架构与界面

侧边栏从上到下：

1. 品牌、Agent 副标题和收藏入口。
2. 三阶段进度：识别岗位、真实经历判断、收藏并准备。
3. 当前岗位卡：岗位、平台、公司、地点、薪资、地址、技能和可滚动 JD。
4. 简历选择与“开始投前准备”。
5. 匹配结论、证据、缺口和下一步动作。
6. 沟通开场白与复制操作。
7. 收藏、修改简历和受控投递入口。
8. 隐私边界说明。

设计要求：

- 侧边栏只纵向滚动，不出现横向滚动条。
- 紧凑工作界面，不使用营销型大标题或嵌套卡片。
- 命令使用图标 + 简短文字；陌生图标提供 `title`。
- 卡片圆角不超过 8 px，保持白色、深绿和中性色的克制组合。
- 状态提示使用 Ant Design Vue `message`，页面悬浮入口使用隔离的轻量状态提示。

## 7. 技术架构

```text
public/manifest.json
  -> public/background.js
  -> public/content/shared.js
  -> public/content/adapters/*.js
  -> public/content/actions.js
  -> public/content/launcher.js
  -> public/content.js

sidepanel.html
  -> src/main.js
  -> src/App.vue
  -> src/api.js
  -> AI 简历后端与网页端
```

边界：

- 平台选择器只能进入适配器。
- 清洗、校验和合并只能进入 `shared.js`。
- 表单动作只能进入 `actions.js`。
- 网页悬浮入口只能负责入口与轻提示。
- 后台只协调 Chrome API 与消息，不复制平台解析规则。
- 侧边栏只消费标准岗位对象，不直接读取宿主网页 DOM。

## 8. 权限与隐私

| 权限 | 用途 |
|---|---|
| `activeTab`、`scripting` | 用户触发后读取当前岗位或回填当前页面 |
| `host_permissions` | 仅覆盖明确支持的招聘网站、官网和 API |
| `sidePanel` | 显示岗位助手 |
| `contextMenus` | 右键快捷操作 |
| `identity` | 网页账号一次性授权回调 |
| `storage` | 保存插件令牌和临时状态 |
| `tabs` | 获取活动页面并打开网页端详情 |

禁止行为：

- 后台批量采集岗位或浏览历史。
- 绕过平台登录、验证码、反爬或风控。
- 读取、上传或保存招聘网站密码和 Cookie。
- 在用户未触发时自动打开侧边栏。
- 未经用户确认自动提交简历或发送消息。

## 9. 非功能需求

### 9.1 兼容性

- Chrome 116 及以上。
- Manifest V3。
- Chromium Edge 可作为兼容目标，但发布前需单独实测。

### 9.2 可靠性

- 热更新重复注入不得产生多重监听或多个悬浮入口。
- 切换岗位后识别失败必须清除旧岗位，不能显示上一次结果。
- Manifest 与后台动态注入文件顺序必须一致。
- 平台提取失败不影响侧边栏打开、账号连接和网页端数据。

### 9.3 性能

- 悬浮入口不得引入 Vue、Ant Design Vue 或额外网络请求。
- 普通页面加载只注入轻量原生 JavaScript；AI 请求只在用户开始准备时发生。
- 轮询 SPA 岗位切换必须有时间上限，不能常驻高频扫描 DOM。

## 10. 验收标准

### 10.1 悬浮入口

- 支持网站打开后只出现一个 AI 入口。
- 不受宿主网站按钮、字体和全局 CSS 影响。
- 鼠标、键盘均能打开侧边栏。
- 点击后侧边栏展示当前岗位或明确失败原因。
- 375 px 与桌面宽度均无正文横向溢出。

### 10.2 岗位识别

- BOSS 切换不同卡片后岗位、公司和 JD 同步变化。
- 51job 能获取岗位、公司、薪资、区域、详细地址、技能和纯净 JD。
- JD 不包含“竞争力分析、微信扫码分享、招聘官、公司信息、工作地址、立即沟通”等独立模块。
- 薪资乱码或标题不一致时不合并错误字段。

### 10.3 收藏

- 收藏接口成功后网页端可查看完整字段。
- 同一岗位重新收藏不新增重复记录。
- 原招聘页链接可以返回准确岗位。
- 旧数据缺失时显示待重新识别提示。

### 10.4 工程检查

```powershell
npm run check:contracts
npm run test:extractor
npm run test:launcher
npm run build:dev
npm run build
```

涉及 Manifest 或内容脚本列表变化后，在 `chrome://extensions/` 重新加载扩展并完成真实页面检查。

## 11. 发布与更新

1. 开发时执行 `npm run dev:watch` 持续构建 `dist`。
2. Chrome 开发者模式加载 `dist`，不是源码根目录和 ZIP 文件。
3. JavaScript/CSS 构建变化后 Vite 会更新 `dist`；Manifest、权限或内容脚本列表变化后仍需点击扩展“重新加载”。
4. 正式分发前执行生产构建并生成 ZIP，再由官网提供下载。
5. 当前不通过 Chrome Web Store 分发，因此没有商店自动更新。

## 12. 指标

- 悬浮入口点击到侧边栏可用的成功率。
- 当前岗位完整识别率与字段缺失率。
- 识别后开始投前准备的转化率。
- 分析后收藏率、返回原招聘页率和修改简历率。
- 同一页面重复识别错误率与跨岗位串数据率。
- 每次成功 Agent 准备的实际 Token 消耗。

指标不得保存用户整页浏览内容，也不得把匹配分数包装成 Offer 成功率。
